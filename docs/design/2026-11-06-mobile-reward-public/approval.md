승인 원본 문서와 테스트 계획을 먼저 문서 PR로 main에 옮기고 두 파일의 Git blob이 승인 원본과 같은지 대조한다. 중앙 실행 근거는 이 동일 본문을 보존한 main 커밋을 approvedCommit으로 결속하며, approvalEvidence에 원래 승인 원본과 사용자 응답 및 blob 대조를 함께 남긴다. squash 병합으로 원래 문서 커밋이 main의 조상이 되지 않는 경우에도 승인 내용을 임의 변경하거나 새 승인으로 꾸미지 않는다.

구현과 출시가 끝날 때까지 원래 테스트 계획의 등급·환경·범위를 낮추지 않는다. 실제 변경 경로가 요구하는 개발 환경 검증은 더하며, 기기만으로 확인할 필수 항목은 별도 소명·명시적 승인 전 접근하지 않는다.
