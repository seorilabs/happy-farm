# 최신 main의 3개 마켓 공개 출시

- 실행 티켓: [#592](https://github.com/seorilabs/happy-farm/issues/592)
- 사용자 지시: 2026-10-24 KST, “Happy Farm 최신 main으로 새 버전 출시 진행해.”
- 제품 기준: `a294d931350dadb62130b9c7b783261f97eb16e6`. 이 문서와 테스트 계획을 병합한 최종 main을 후보로 고정한다.
- 대상과 끝 지점: 기존 Google Play, App Store, AppsInToss의 공개 버전 조회까지. 국가, 무료 가격, 기존 공개 방식을 유지하며 Play는 완전 출시한다.

## 범위와 승인 기록

이 요청은 이전 구현과 병합 요청의 출시 범위를 공개까지 넓힌다. 개발 정책의 태그 전 범위 확장 절차에 따라 이 지시를 출시 승인 근거로 기록한다. 게임 코드, 제품 정책, SDK 설정, 광고 단위, 저장 규약과 기능 목록은 바꾸지 않는다. 버전 번호는 사용자 확인 후 중앙 원장과 태그 워크플로로 발행한다. 패키지 파일의 개발 버전을 수동으로 고치지 않는다.

이전 [설계 10건](../2026-10-23-open-issues/README.md)과 원래 테스트 계획, 승인 커밋 및 판정은 보존한다. #512의 새 화면 검수는 `76de0411818a649babdf7e803e13e774551b54bc`에서 승인된 4, 5, 6회로 완료됐다. 잘못된 최초 기록과 정정도 원본 그대로 유지한다. 이번에는 새 화면이나 UI 개편을 구현하지 않으므로 출시 전 전체 회귀를 별도로 실행하며, 이전 회차를 새 후보의 통과 횟수나 실제 실행으로 바꾸지 않는다.

L3, 개발 환경, 전체 26개 기능과 기반 기능 재실행을 계획한다. 이전에 승인된 6개 기반 기능의 개발 환경 대체 범위를 유지한다. 실제 네이티브 SDK, OS 광고와 서버 보상 전달을 대체 구현의 통과로 표시하지 않는다. 기기 사용, 시뮬레이터 설치와 실행은 승인에 포함하지 않는다. 개발 환경으로 확인할 수 없는 필수 항목이 남으면 대상과 이유, 시간과 데이터 영향을 소명한 뒤 별도 승인받는다.

공식 사이트 개인정보 처리방침은 #520과 `seorilabs/seorilabs-official#89`의 Ready 상태를 유지한다. GA4 보관 설정, 서버 삭제 주기, 국외 처리 사실의 확인 자료가 없으므로 미확인 사실을 채우거나 공개하지 않는다. 현재 공개 정책과 실제 앱의 불일치가 제출을 막으면 해당 마켓을 차단으로 기록한다. 공개되지 않은 제품별 정책 URL로 교체하지 않는다.

사용자 리뷰의 “광고 없음”은 개발자가 편집할 수 있는 문구와 구분한다. 리뷰 삭제, 평점 초기화나 개발자 답변을 수행하지 않는다. 실제 등록 문구에 같은 주장이 있으면 해당 문구만 수정하고 다시 읽는다.

## 실행과 실패 처리

`최종 main 고정 → 독립 L3 전체 회귀 → 중앙 검증 → 원장 태그 발행 → 검토한 출시노트 → 마켓별 빌드와 테스트 업로드 → 제출 전 검증 → 심사와 공개 → 실제 버전 조회` 순으로 진행한다. 같은 후보 SHA의 작은 근거 JSON은 소스 밖에 만들고 태그 Release 자산에 결속한다.

Google Play는 `com.seorilabs.happyfarm`의 실제 개발자 계정, 서비스 계정 접근과 업로드 인증서, 원장 versionCode, internal과 production의 같은 AAB를 확인한다. App Store는 앱 `6775451733`, bundle ID, 실제 태그 receipt의 빌드 번호, 8개 활성 언어와 이미지, 실제 선택 빌드와 제출 상태를 확인한다. public 저장소의 기존 GitHub Actions 경로를 사용한다. AppsInToss는 `happy-farm`, workspace `38345`, miniapp `31877`, canonical memo의 소스와 파일 해시, 배포 ID와 검토 및 공개 상태를 확인한다. 영구 식별자와 마켓 소유자는 변경 전에 다시 읽는다.

한 마켓의 실패로 다른 마켓을 멈추지 않는다. 파이프라인이나 중앙 계약 수정이 필요하거나, 자격증명과 서명 또는 receipt가 다르거나, 중앙 검증이 막거나, 미확정 정책 판단이 필요하면 해당 레인을 중단하고 구체적인 근거를 남긴다. 실패 후보의 태그를 옮기지 않는다. 제품 변경이 필요하면 PR과 새 후보로 진행한다. 국가와 가격 변경, 계정 권한 변경, 자격증명 생성 및 교체, 지원팀 연락은 수행하지 않는다.

## 인수조건과 검증

| 조건 | 검증과 증거 |
|---|---|
| AC-1 소스와 승인 결속 | 최종 main과 실행, 태그 receipt, artifact, 마켓 버전의 SHA와 번호 대조 |
| AC-2 현재 후보 전체 회귀 | 다른 에이전트의 RN 개발 화면 실제 입력, 저장과 재실행, 오류와 복구, 서비스 감시 실행. 26개 기능 모두 실행 |
| AC-3 정적 검사와 빌드 | lint, 타입, 전체 테스트, i18n, 경제, 아키텍처, 마켓 설정 검사와 AIT 빌드. 마켓 서명 산출물은 각 레인에서 검사 |
| AC-4 마켓 문구와 정책 | 모든 활성 언어와 이미지, 실제 선택된 출시노트, 기존 개인정보 및 지원 URL, SDK와 신고 항목 대조. 저장 후 다시 읽기 |
| AC-5 공개 완료 판정 | 업로드, 처리, 제출, 승인, 공개 및 버전 조회를 별도 기록. 미실행과 외부 차단은 통과로 기록하지 않음 |

제품을 바꾸지 않는 출시 작업이므로 새 실패 테스트를 만드는 대신 기존 회귀와 중앙 검증, 서명 및 마켓 조회를 사용한다. 같은 기능의 예전 실행을 새 실행으로 복사하지 않는다. 개발 대체 환경과 실제 네이티브 실행은 보고서에서 구분한다. 증적 원본은 NAS1dual에 스트림 복사하고 크기와 SHA-256을 직접 읽어 대조한 뒤 로컬 작업 산출물을 정리한다. Git에는 작은 결과 요약과 검증 목록, NAS 참조를 남긴다.

출시 후 문제는 고정된 마켓 버전과 원본 증거로 조사한다. AIT의 기존 공개 번들 복귀는 현재 상태와 권한을 다시 확인하며, 스토어는 임의 다운그레이드 대신 수정 PR과 새 후보로 처리한다. 심사 중인 상태를 완료로 표시하지 않는다.
